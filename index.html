Duplicate Value Handling Policy

In standard Binary Search, when identical numbers exist in the array (e.g. [2, 4, 4, 4, 6] with target 4), the algorithm immediately halts at the first midpoint where A[mid] == Target. Standard Binary Search returns any valid matching index rather than guaranteeing the leftmost or rightmost occurrence.

1. Formal Specification & Invariant

Binary search operates on an array A[0..n-1] sorted such that A[i] ≤ A[j] for all i < j. The loop maintains the fundamental loop invariant: if target ∈ A, then target ∈ A[low..high]. At each iteration, comparing target with A[mid] eliminates at least ⌊(high - low + 1) / 2⌋ candidates, halving the problem size.

2. Recurrence Relation & Master Theorem

The worst-case recurrence is T(n) = T(n / 2) + O(1), where a = 1, b = 2, and f(n) = O(1). By the Master Theorem (Case 2 with c = log_b(a) = log_2(1) = 0), T(n) = Θ(log n). Maximum comparisons = ⌊log&sub2; n⌋ + 1.

3. Common Pitfalls & Edge Cases
  • Unsorted Array: Binary search produces incorrect results on unsorted data because the invariant is broken.
  • Integer Overflow: In low-level languages (C++/Java), (low + high) / 2 can overflow for large indices. The safe formulation is low + ((high - low) / 2).
  • Duplicate Values: Standard binary search terminates at the first matching midpoint, returning any matching index. For the first occurrence, left-boundary logic must continue searching left (high = mid - 1) even when a match is found.
  • Off-by-One Termination: Using while (low < high) instead of while (low ≤ high) will fail to evaluate single-element candidate ranges.

COA Core Concepts Guide: Number Systems & Machine Architecture Syllabus: COA Module 1 • Bits, Bytes, Radix Representation & Two's Complement
Toggle Guide ▾
1. What a Bit and a Byte Are

A bit (binary digit) is the atomic unit of digital information, holding either a 0 (low voltage) or 1 (high voltage). A byte is a contiguous group of 8 bits. A single byte can encode 2⁸ = 256 distinct bit patterns (from 00000000 to 11111111), serving as the standard addressable memory unit in modern computing architectures.

2. Why Computers Use Binary (Base 2)

Modern microprocessors are built from billions of microscopic silicon MOSFET transistors acting as electronic switches. Having only two discrete physical states (ON = saturation voltage, OFF = cut-off voltage) provides immense noise immunity, thermal stability, and circuit simplicity compared to multi-voltage analog systems.

3. Why Octal and Hexadecimal are Useful Shorthand

Because 2³ = 8 and 2⁴ = 16, exactly 3 bits map to 1 octal digit, and exactly 4 bits (1 nibble) map to 1 hexadecimal character (0-9, A-F). Instead of reading 32 unwieldy bits like 11111111000000001010101001010101, engineers represent it cleanly as 0xFF00AA55 without any numerical rounding.

4. How Positional Radix Notation Works

Every positional number system represents a magnitude N as the polynomial sum of digit weights: N = ∑ (dᵢ × bⁱ) where b ≥ 2 is the radix and 0 ≤ dᵢ < b. Position i denotes the exponent of the base: for binary, weights are powers of 2 (1, 2, 4, 8, 16...); for decimal, powers of 10; for hexadecimal, powers of 16.

5. Why Fixed-Width Binary Matters in Computer Architecture

Physical CPU registers have rigid hardware bit widths (e.g., 8-bit, 16-bit, 32-bit, 64-bit). Arithmetic operates strictly modulo 2ⁿ. When an operation exceeds the register capacity, hardware overflow occurs, and the carry bit out of the MSB is either stored in a processor status flag or discarded.

6. Why Hardware ALUs Universalize Two's Complement

In sign-magnitude or 1's complement, there are two distinct encodings for zero (+0 and -0), requiring extra comparison logic. In Two's Complement:

  • Zero has a single, unique encoding (00000000).
  • Subtraction A - B is executed as A + (-B) where -B = ~B + 1, using identical binary adder circuitry without separate subtractors.
  • The MSB carries negative weight -2ⁿ⁻¹, while all other bits represent positive weights, naturally enforcing the signed range [-2ⁿ⁻¹, 2ⁿ⁻¹ - 1].

1. Formal Definition of a DFA

A Deterministic Finite Automaton is a 5-tuple M = (Q, Σ, δ, q0, F):

  • Q: A finite set of internal control states (here { q0, q1, q2 }).
  • Σ: A finite set of input alphabet symbols (here binary { 0, 1 }).
  • δ: Q × Σ → Q: The deterministic transition function with exactly one target state per input.
  • q0 ∈ Q: The designated initial start state (here q0).
  • F ⊆ Q: The set of accepting / final states (here { q2 }).
2. Language Suffix Invariant for L = { w | w ends in "01" }

Every state in this DFA represents an equivalence class of string suffixes:

  • State q0: Represents the state where the most recent symbol was '1' (not preceded by 0) or the string is empty. No progress toward "01".
  • State q1: Represents strings ending in '0'. If a '1' arrives next, we achieve the target suffix "01" (moving to q2). If another '0' arrives, we remain in q1 because the string still ends in '0'.
  • State q2 (Accept): Represents strings ending in "01". If '0' arrives, the suffix becomes "010" which ends in '0', so δ(q2, 0) = q1. If '1' arrives, the suffix becomes "011", completely resetting the progress to q0.
3. Common Pitfalls & Misconceptions
  • Intermediate State Acceptance: A string is NOT accepted simply because it visits q2 at some intermediate step; acceptance is evaluated strictly upon consuming the final symbol of the input.
  • Empty String (ε): The empty string executes 0 transitions and halts in q0. Because q0 ∉ F, ε is correctly rejected.
  • Non-Determinism: Unlike NFAs, every state must have an explicit outgoing transition for every symbol in Σ, with no ambiguity and zero ε-transitions.
